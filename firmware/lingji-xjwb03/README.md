# 灵机 XJWB03 固件

本目录用于 **XJWB03-DevKIT-V1 + LJX40-Audio-KIT-V1** 的独立固件、构建和烧录。仓库原有的 `firmware/src/` 仍是 NodeHexa 运动控制板的 PlatformIO 工程；两块板分别构建和烧录。

当前状态：已复制官方 SDK、安装 ESP-IDF 工具链，云端语音问答和两轮连续对话已实测。BF3901 官方帧校验通过，板上现运行摄像头与云端语音合并固件。本机[摄像头预览页](CAMERA_PREVIEW.md)持续更新画面；可点击按钮或在唤醒后提出视觉问题，按需调用千问。[视觉到语音 Agent 桥接](VISION_VOICE_BRIDGE.md)已完成一次按钮触发的实机闭环，语音触发也已送达视觉模型与 Agent。为避免 Agent 在视觉结果到达前先说“看不到”，[角色定义补充规则](AGENT_VISUAL_CONTEXT.md)已于 2026-10-28 作为原版“灵犀”V2 发布生效；新版设备端行为尚待实测。待机云端麦克风上行实测关闭。两板 UART、长时间并行稳定性、人体坐姿识别和四项偏好跨会话持久化尚未完成。

## 现在可做的语音测试

在 macOS 终端进入本目录，首次配置工具链时运行 `./lingji.sh setup`。板上当前是云端语音与摄像头合并固件：`CONFIG_NODEHEXA_VOICE_SELFTEST=0`、`CONFIG_APP_CAMERA_TEST=1`、`CONFIG_QM_POSE_SUPPORT=0`。此前本地自检固件已验证开机音和唤醒提示音，云端语音固件已完成配网和连续对话实测。重新构建前须先按目标功能核对宏并在本机配置产品身份。实测模块把该唤醒事件记作“你好小鹰”。

烧录用 `./lingji.sh flash /dev/cu.usbmodem...`，端口必须显式给出。脚本先核对 USB 桥 VID/PID、ESP32-S3 和 16 MB Flash，备份整片 Flash 到被 Git 忽略的 `backups/`，再写入当前构建的全部镜像。查看串口运行日志用 `./lingji.sh monitor /dev/cu.usbmodem...`，退出监视器按 `Ctrl+]`。摄像头已接线；NodeHexa 的串口线还没有接入。

云端固件已从**本机忽略文件** `project_identity.local.h` 读取产品身份并烧录。官方小程序 BLE 配网、Wi-Fi、动态注册和云连接均已验证；接着验证连续对话。详细步骤见 [CLOUD_SETUP.md](CLOUD_SETUP.md)。不要将 SECRET 发在聊天中或提交到 Git。

## 产品理解

目标是一个有陪伴感的桌面机器人：先满足比赛的真实硬件与 Agent 闭环要求，再让语言和动作交互更灵活。演示优先级为 **B：情绪对话与鼓励 > C：多轮跟进、调整建议与动作 > A：标准姿态提醒**。姿态与专注功能是可触发的能力，不应把互动限制成固定口令。只记住用户明确给出的称呼、提醒语气、动作轻重和喜欢的休息方式，不从音视频暗中推断长期偏好。尚未确定主动提醒频率、允许的机器人动作范围和用户拒绝提醒后的具体规则。

## 两板职责与连接

灵机板负责语音输入输出、摄像头采集/姿态识别、灵机平台 Agent 会话、偏好记忆和高层动作决策。NodeHexa 板负责步态、舵机、电池保护、动作边界和停止指令；Agent 不直接输出舵机角度。

首选两板之间使用 3.3 V UART，灵机板自身用 Wi-Fi 接入互联网。灵机板的 GPIO17（TX）/GPIO18（RX）是待实物核验的候选引脚；NodeHexa 现有 UART2 为 GPIO16（RX）/GPIO17（TX），115200 8N1。交叉连接 TX/RX 并共地，两板分别供电。不得占用灵机板音频 UART 的 GPIO38/39/40 或日志 UART 的 GPIO43/44。具体三线连接和上电检查见 [ROBOT_LINK_WIRING.md](ROBOT_LINK_WIRING.md)。

通信沿用 NodeHexa 的 UART v2 帧（序号、CRC、应答和心跳），只传高层动作与状态。动作命令必须有允许列表、幅度/时长上限与超时停止；失联停止行为需要实机验证，不能仅凭“外设离线”状态推断。

## 写代码与烧录顺序

1. **基线启动**：先用无需平台密钥的本地固件检查开机音和唤醒；Agent 创建并绑定后，再用本机未跟踪的 PID/SECRET 检查配网与连续对话。
2. **单项视觉**：按实际摄像头模组与转接板核验 3.3 V 接线；单独验证取流、至少三种状态识别及资源占用，再与语音并行测试。当前 SDK 的姿态示例只识别内置图片，摄像头任务只记录帧统计；实时画面送入姿态模型需要我们编写并验证。
3. **两板通信**：在灵机应用中加 `robot_link` 模块，完成 HELLO、命令、ACK、心跳和状态回传；先让 NodeHexa 执行有限的安全动作，再接 Agent 决策。
4. **互动与记忆**：把语音意图、视觉事件和机器人状态交给交互状态机；仅持久化用户明确设定的称呼、提醒语气、动作轻重和喜欢的休息方式，允许用户修改或清除。
5. **整机验证**：分别测语音、视觉、运动，再测连续对话中途改意图、拒绝提醒、失联/低电量/紧急停止，以及比赛要求的完整感知—判断—反馈—动作闭环。

首次烧录或改分区时，按照**实际构建产物**核对 `flash_args`，写入该配置所需的全部镜像；启用姿态模型时必须包含模型分区，不能只写应用分区。关闭姿态功能后的镜像条目数须以实际 `flash_args` 为准，不沿用文档中的固定“六个”假设。烧录前先备份当前 Flash 并确认串口对应的是灵机板。任何烧录脚本都必须显式指定端口，禁止自动选择当前同时连接的 NodeHexa 板。
