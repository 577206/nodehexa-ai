# 灵机 XJWB03 固件

本目录用于 **XJWB03-DevKIT-V1 + LJX40-Audio-KIT-V1** 的独立固件、构建和烧录。仓库原有的 `firmware/src/` 仍是 NodeHexa 运动控制板的 PlatformIO 工程；两块板分别构建和烧录。

当前配置已切换为 **[千问全模态直连](QWEN_DIRECT.md)**：本地唤醒、麦克风采集、摄像头和喇叭留在灵机板，电脑通过 Wi-Fi 连接板子，再用原有本地密钥连接 `qwen3.8-omni-flash-realtime`。不再启动灵机平台 Agent。普通聊天、按需视觉工具和运动意图由同一会话处理。运动默认禁用，启用后仍受底盘在线状态和固定动作白名单约束。

2026-10-30 已编译并烧录直连固件，Wi-Fi 接口与摄像头取图正常，云 Agent 状态为关闭。原密钥的实时连接、语音生成、当前帧理解、运动/停止工具选择已实测；板端真实唤醒、连续麦克风对话和喇叭效果正在进行用户验收。当前机器人 UART 未在线，不能宣布实际运动通过。供电仍需完成充电宝条件下的复测。

## 当前测试入口

旧云端方案、配网与历史验证记录保留在 [CLOUD_SETUP.md](CLOUD_SETUP.md)、[WIFI_BRIDGE.md](WIFI_BRIDGE.md)、[CAMERA_PREVIEW.md](CAMERA_PREVIEW.md) 中；当前运行方式以 [QWEN_DIRECT.md](QWEN_DIRECT.md) 为准。旧应用已备份，详见该文档的回退说明。密钥与令牌仍只存本机忽略文件，不提交 Git。

## 产品理解

最新的双层磁吸结构、手机实体托管、合体登场动作和电脑无线协作需求以仓库根目录的[产品需求与结构](../../PRODUCT_REQUIREMENTS.md)为准。

目标是一个有陪伴感的桌面机器人：先满足比赛的真实硬件与 Agent 闭环要求，再让语言和动作交互更灵活。演示优先级为 **B：情绪对话与鼓励 > C：多轮跟进、调整建议与动作 > A：标准姿态提醒**。姿态与专注功能是可触发的能力，不应把互动限制成固定口令。只记住用户明确给出的称呼、提醒语气、动作轻重和喜欢的休息方式，不从音视频暗中推断长期偏好。尚未确定主动提醒频率、允许的机器人动作范围和用户拒绝提醒后的具体规则。

## 两板职责与连接

灵机板负责语音输入输出、摄像头采集/姿态识别、灵机平台 Agent 会话、偏好记忆和高层动作决策。NodeHexa 板负责步态、舵机、电池保护、动作边界和停止指令；Agent 不直接输出舵机角度。

两板之间使用 3.3 V UART，灵机板自身用 Wi-Fi 接入互联网。灵机板 GPIO17（TX）/GPIO18（RX）与 NodeHexa GPIO16（板上丝印 `P16`，RX）/GPIO17（丝印 `P17`，TX）已完成 115200 8N1 双向握手。交叉连接 TX/RX 并共地，两板分别供电。不得占用灵机板音频 UART 的 GPIO38/39/40 或日志 UART 的 GPIO43/44。具体三线连接和上电检查见 [ROBOT_LINK_WIRING.md](ROBOT_LINK_WIRING.md)。

通信沿用 NodeHexa 的 UART v2 帧（序号、CRC、应答和心跳）；灵机板已有固定动作白名单和停止命令，机器人台架模式下拒绝运动。预设动作只有有限周期；连续行走所需的本地超时自动停止与失联停止行为尚未完成，也未做实机运动测试。

## 写代码与烧录顺序

1. **基线启动**：先用无需平台密钥的本地固件检查开机音和唤醒；Agent 创建并绑定后，再用本机未跟踪的 PID/SECRET 检查配网与连续对话。
2. **单项视觉**：按实际摄像头模组与转接板核验 3.3 V 接线；单独验证取流、至少三种状态识别及资源占用，再与语音并行测试。当前 SDK 的姿态示例只识别内置图片，摄像头任务只记录帧统计；实时画面送入姿态模型需要我们编写并验证。
3. **两板通信**：`robot_link` 已完成 HELLO/心跳，后续增加受限动作命令、ACK 与状态回传；先恢复合规格机器人供电并验证安全动作，再接 Agent 决策。
4. **互动与记忆**：把语音意图、视觉事件和机器人状态交给交互状态机；仅持久化用户明确设定的称呼、提醒语气、动作轻重和喜欢的休息方式，允许用户修改或清除。
5. **整机验证**：分别测语音、视觉、运动，再测连续对话中途改意图、拒绝提醒、失联/低电量/紧急停止，以及比赛要求的完整感知—判断—反馈—动作闭环。

首次烧录或改分区时，按照**实际构建产物**核对 `flash_args`，写入该配置所需的全部镜像；启用姿态模型时必须包含模型分区，不能只写应用分区。关闭姿态功能后的镜像条目数须以实际 `flash_args` 为准，不沿用文档中的固定“六个”假设。烧录前先备份当前 Flash 并确认串口对应的是灵机板。任何烧录脚本都必须显式指定端口，禁止自动选择当前同时连接的 NodeHexa 板。
