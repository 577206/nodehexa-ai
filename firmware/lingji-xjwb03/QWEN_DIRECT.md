# 灵犀：千问直连语音、视觉与动作

2026-10-30。用户已向比赛负责人确认可以不使用灵机平台 Agent。本配置启动硬件音频、已保存的 Wi-Fi、摄像头和机器人 UART，不启动灵机云端 Agent、MQTT 对话或云端 TTS。旧路径保留用于回退。

## 完整路径

```text
LJX40 本地唤醒
  → XJWB03 原生 16 kHz / 20 ms Opus
  → 带本地令牌的 Wi-Fi 音频接口
  → 电脑解码为 PCM16
  → qwen3.8-omni-flash-realtime 的同一 WebSocket 会话
       ├ 普通聊天：直接生成语音
       ├ look 工具：电脑按需取 BF3901 当前一帧 → 同一会话理解并回答
       └ move 工具：固定动作白名单 → XJWB03 UART → NodeHexa 接收回执
  → 电脑拦截工具调用前的临时话语，把最终回答的 24 kHz PCM 转为 16 kHz Opus
  → Wi-Fi → LJX40 → 喇叭
```

没有另一个 Agent 先答“我看不到”，也不再把系统提示词作为需要朗读的文本注入。视觉功能只在工具调用时上传当前一帧。网页按钮“获取当前一帧”只在局域网内取图，不调用模型。旧图片带取图时间，不能冒充实时预览。

实时接口实测不接受本项目所尝试的 `conversation.item.create/input_image` 格式。采用已验证的 `input_audio_buffer.append`（200 ms 静音载体）→ `input_image_buffer.append` → `input_audio_buffer.commit`，收到 committed 后才 `response.create`。工具结果与图片都进入原会话。取图期间暂时关闭服务端 VAD，回答后恢复。

## 使用

电脑与灵机板在同一局域网；灵机板用电脑 USB 或稳定的 5 V 电源供电。电脑仍是必需的桥接服务。

沿用被忽略的 `.env.local`：`DASHSCOPE_API_KEY`、`LINGXI_BOARD_URL`、`LINGXI_BRIDGE_TOKEN`。现有 Chat Completions 的 BASE_URL / VISION_MODEL 留给旧路径，不控制新实时模型。

实时模型是 `qwen3.8-omni-flash-realtime`，目前实测可使用原有密钥和兼容域名 `wss://dashscope.aliyuncs.com/api-ws/v1/realtime`。密钥只在电脑后端，不写进固件、页面或诊断输出。

工作区根目录建立 `.venv-omni`，安装 `requirements-omni.txt`。启动：

```sh
./lingji.sh omni
```

打开 <http://127.0.0.1:8765/>。`preview-wifi` 在 QWEN_DIRECT 配置下也转到新服务。不要同时启动旧 `camera_web.py`。

说“你好，小灵”后提问。喇叭播报时暂停麦克风上传，播放排空后继续听下一句话；静默约 30 秒进入本地待唤醒。播报中可用本地唤醒词取消旧会话并重新开始。目前采用半双工回声隔离，尚未承诺普通说话即可打断播报。

每次本地唤醒建立一个新的会话代号，旧代号的音频被拒绝。电脑把最多 24 条对话文本、身份与四项明确偏好保存到被 Git 忽略的 `omni_memory.local.json`（权限 0600）。重启后保留；不保存麦克风录音和历史照片。访问 `/memory` 可编辑身份、偏好、单条上下文，或清空最近对话。修改于下次唤醒生效；页面可查看当前/下次会话指令。

电脑服务启动时运动默认禁用，确认机体架空、供电正常后在页面开启。固定动作清单见下文；板端决定每步幅度。停止不受运动开关限制。回执仅说明底盘接受命令，不代表已经完成位移。离线、拒绝或回执超时均不自动重发运动。

## 电脑直接控制动作（2026-10-31）

打开 `http://127.0.0.1:8765/#motion`，开启“允许运动”后，方向键或动作卡片直接执行一个固定预设，无需唤醒或等待模型理解。方向区提供前进、后退、左右转、左右移、站姿和扭腰；动作库按行走、姿态、表演、控制分类，沿用全部 18 个预设及原有周期上限。没有新增独立速度或距离设置。

右侧显示底盘接收回执。发送中阻止重复运动请求，停止仍可抢占；顶部停止键、方向区停止键和运动页的 Esc 都会发送停止并禁用运动。关闭运动开关也会发送停止。断网或回执超时不会自动重试。底盘离线、台架禁动或服务不可达时，普通动作按钮禁用；停止不受这些条件阻挡，但网络停止不能替代硬件断电。

新增本机 `POST /api/motion`，请求只允许 `{"action":"固定动作名"}`，复用语音的 `Controller.move`。接口保留本机 Host/Origin 校验。运动状态用最新板端状态检查，不依赖千问对话是否成功。

验证：`python -m pytest -q test_omni_motion.py test_omni.py test_omni_memory.py test_motion_presets.py`，23 项通过；隔离模拟底盘已验证网页开关、前进按钮、表演分类及动作卡片。实体底盘当前离线，本次尚未实机验证按钮驱动动作。

## 资源与恢复边界

- 板端上行 32 包、下行 64 包，每包不超过 255 字节；不存在无限音频列表。
- 电脑输出队列有界，发生积压、协议错误或模型超时即结束本轮，不继续注入旧回答。
- 电脑失联约 6 秒后板端停播放、关上行；思考/播报窗口最多 60 秒。唤醒可清掉旧队列。
- 摄像头保持底层取流；JPEG 仅按需生成，发送后释放。网页只保留最近一帧。
- 新固件继续使用已保存的 Wi-Fi。更换网络仍需适配现有配网流程；本次没有新增脱离灵机小程序的配网页面。
- 局域网接口有令牌但使用 HTTP；仅在可信局域网内使用，不映射公网。

- 真实接口拒绝旧代号 409、格式错误 400、缺少令牌 403。
- 八项自动测试通过。用户实机声音验收及充电宝复测尚待完成；此项为当时状态；后续无线运动验收见下文。
- 合成中文录音经过实际应用的 Opus 解码 → 千问 VAD/语音识别 → 工具调用 → 回答编码，连续两轮通过。第一轮“你叫什么名字”返回 116 个可解码播放包；第二轮看图取 1 帧、返回 426 个播放包。此测试模拟麦克风输入和喇叭接收端，不替代真实硬件收音与听感验收。

## 2026-10-30 播报截断修复

用户反馈“只说开头”，串口确认 `play write failed -2`：推送音频队列在 100 ms 内未腾出空间，应用立即 idle，截断剩余语音。另发现 VB701N 驱动未声明 DRAIN 能力，开机音结束返回 `-6`（ENOSYS）。

- 电脑每批最多 10 个 20 ms 包，按音频时长限速；网络变慢后不追赶突发发送。
- 固件写入等待从 100 ms 调整至 1000 ms，仍保留有限等待和错误退出。
- VB701N UART 根据前一批 PCM 实际时长限速，避免把 20 ms 声音每 5 ms 塞入模块；10 ms 开机静音帧也独立计时。
- 驱动声明 DRAIN 能力，并在软件队列排空后等待最后一批 PCM 的预计时长。模块没有物理播放完成回执，因此这是基于发送时钟的尾音等待，不是硬件听感检测。
- 串口新增本轮成功写入包数、预计音频时长、实际运行时长、完成结果。

验证：11 项自动测试通过（含真实 C 驱动代码的模拟时钟测试，覆盖节拍、尾音等待、超时与取消）；应用编译、烧录及校验通过。开机音实机日志已由 `ret=-6` 变成 `ret=0 frames=86/86`。长句和看图回答的用户听感复测待确认。页面身份/记忆编辑仍按用户要求排在声音修复验收之后。

## 无线运动、身份记忆与结束对话更新

- 用户确认：充电宝无线模式下，语音要求前进，六条腿完成一轮动作后停止，语音正常。UART 双向在线、禁动模式关闭；停止和前进收到成功回执。侧移与转向尚未逐项做物理验收。
- 最初测试后曾关闭运动开关；随后按用户要求重新开启。电脑服务重启仍默认禁用，需要重新开启。
- `/memory` 页面提供名字、角色、表达方式、补充设定，以及称呼/提醒语气/动作轻重/休息偏好四项编辑；支持最近 24 条文本的修改、逐条删除、清空。页面无 API 密钥。保存采用原子替换，版本冲突不会覆盖新偏好。
- 模型的 `remember` 工具只接受四项偏好，提示它仅在用户明确要求时保存；真实千问测试已成功调用并在后续回复使用称呼。测试使用独立的内存存储，没有污染用户文件。
- 新增 `end_conversation`：明确结束聊天时先调用工具，再简短道别；完整音频下发后等待板端结束播放，再发送 idle。开始结束流程即停止向千问提交新语音。网页“结束本次对话”可立即取消语音，不等同运动停止。
- “停下来/别走了”映射运动 stop，“先这样/休息吧”映射结束聊天；仍需要实机验证自然表达的稳定性。
- 17 项测试通过，含持久化、失败时保留旧内容、旧版本冲突、页面接口同源校验、结束等待真实播放状态；真实模型成功执行 remember 和 end_conversation（扬声器模拟接收）。新的道别/退出流程实机听感待用户确认。
- 开机语音问候“已准备好”尚未加入，当前仍为本地开机音。唤醒后直接听，不插入长问候。

## 全部既有动作开放（2026-10-30）

统一清单为 `motion_presets.json`，`generate_motion_presets.py` 生成板端 `robot_presets.inc`；编译前检查二者一致。模型只能选择固定名称，不能指定舵机角度或无限循环。页面展示每项口令、执行上限和板端是否支持。工具列表按当前板端公布的能力过滤，旧固件只开放原有 7 项。

| 类别 | 动作 | 固定执行上限 |
| --- | --- | --- |
| 行走 | 前进、后退、抬腿爬行步态 | 各 1 个周期 |
| 行走 | 快步前进、左转、右转、左移、右移 | 各 0.5 个周期 |
| 姿态 | 恢复待机站姿、机身 X/Y/Z 轴摆动、扭动身体、节奏摇摆 | 各 1 个周期 |

共 18 项。自由舞可能包含位移；抬腿爬行只是预设步态，不包含自主避障。轴向摆动不等于完整转圈，位移与转角尚未标定。单腿角度调试不属于整机预设动作，本次未开放给模型。

验证：20 项自动测试通过；真实千问对“组合表演”“快步前进”“恢复站姿”选中正确工具参数（未触发硬件运动）。新应用已烧录并通过哈希校验，板端报告 `presetVersion=2` 和全部 18 项，页面运动开关已开启。烧录后的检查中底盘 `online=false`、接收计数为 0，新增动作物理验收待底盘恢复通信后逐项进行。此前用户已确认前进完成一轮且语音正常。

## 工作台界面改版

左侧固定导航，右侧显示对话、运动控制、人格工作室、记忆与偏好、视觉、设备状态。桌面显示完整导航名称；窄窗口收为图标栏。页面沿用原有接口，刷新即可使用，无需重启语音服务或烧录固件。

- 对话页显示最近 24 条真实对话文字，底部为板上麦克风的语音状态与结束入口；目前不是键盘输入聊天框。
- 人格工作室提供温柔陪伴、专注监督、狂暴吐槽三种原创预设。选择先填入草稿，可继续编辑；保存后下次唤醒生效。不会自动替换当前人格或音色。
- 预设保留名字和四项偏好。“保存偏好”仅更新偏好，保留尚未保存的人格草稿；“保存人格与偏好”一起保存两者。当前身份仍使用既有本地持久化机制，尚无多个自定义人格档案的独立存储。
- 运动页提供启用开关、停止并禁用、18 项动作分类与语音口令。查看口令不会执行动作；不提供未标定的速度、厘米数或角度滑块。
- 监督人格用于对话督促，不代表后台计时或手机托管检测已经实现。狂暴人格只是说话风格，不提高运动幅度。
- 记忆和动作相关 9 项回归测试通过，页面脚本语法与重复 ID 检查通过。原对话记录、偏好和运动开关不因页面改版而重置。
