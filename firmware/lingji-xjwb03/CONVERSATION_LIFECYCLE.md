# 灵犀对话开始与结束（2026-10-30）

用户优先验证充电宝供电下的无线语音和视觉。无线语音运动首轮验收后，已更新电脑端记忆编辑及结束会话逻辑；没有改动已验收的板上播放固件。

## 交互方案与实现状态

| 场景 | 期望行为 | 当前状态 |
|---|---|---|
| 开机 | 本地短提示音；联网和电脑服务就绪后可选一次“已准备好”，不要不断重复欢迎 | 已有本地开机音；就绪语句待实现 |
| 待机 | 仅本地唤醒词检测，不向电脑/模型上传声音 | 已实现 |
| 用户唤醒 | 短提示音即可，直接听用户说话，不用长问候抢话 | 已有本地唤醒路径；硬件提示音以听测为准 |
| 普通问题 | 同一千问会话理解和语音回答 | 已实现，USB 供电下已通过听测 |
| 看画面 | 模型调用 look，只取当前一帧，同一模型生成回答 | 已实现，USB 供电下已通过听测 |
| 播放 | 暂停语音上传，完整播放后恢复听取下一句话 | 修复限速和尾音排空，用户确认聊天/看图均完整 |
| 静默退出 | 回复结束恢复听取后约 30 秒无新发言，安静回待机，不额外叫醒用户 | 已有板端窗口；需要无线下验证 |
| 明确结束 | “先这样”“不用了”“休息吧”等由语义判断调用结束工具，简短道别播完再回待机 | 已实现 end_conversation + 播完退出；真实模型和状态模拟测试通过，实机听测待确认 |
| 长时间连续对话 | 上下文有界，必要时提示重新唤醒；不在一句话中途强行切断 | 最多 20 次回复，现改为最后一条播完再关闭 |
| 网络断开 | 关闭上行和播放，自动恢复连接后仍等用户唤醒，不自行继续旧话 | 板端有 6 秒失联保护 |

结束必须有实际状态切换：不能仅让模型说“再见”却继续上传声音。结束工具的实现应带“播完退出”标志，经播放队列排空和板端返回后，再发 idle 命令；不得在 response.done（云端生成完毕）时立即停止喇叭。无声音回复也应能退出。视觉和动作流程不能被结束工具自动重复触发。

开机就绪问候需与联网状态区分，没联网时不能声称已能聊天。进入待机的静默计时应从播放完成开始，讲话中途延长；模型思考和工具执行使用各自超时，不冒充用户静默。

## 无线验收

1. 电脑服务持续运行、同一局域网，灵机板从 Mac USB 改接充电宝；确认新的启动代号和恢复在线。
2. 连续三轮普通问题、画面描述、普通追问，逐轮听完再说，核对新照片时间及完整回答。
3. 不说话约 40 秒，确认 audioState=0，audioIn 不再增加；再次唤醒应恢复对话。
4. 至少保持供电两分钟，确认无低负载自动断电、反复重启或只剩电源灯的情况。
5. 底盘运动单独验收，不把语音/视觉成功当作运动通过。

首轮无线运动：用户已确认前进一轮并停止、语音正常。其他动作及静默退出的持续稳定性仍需后续验收。
