# BF3901 画面与灵犀语音 Agent 桥接

当前实现是按需联动：本机预览页持续显示摄像头帧，但不持续调用模型。点击“描述并让灵犀语音回应”时，本机服务先确认灵机板上的桥接命令和云连接可用，再取当时的一帧交给千问生成一句短的视觉摘要。服务把摘要经 USB 调试串口发回灵机板；板端 `vision_bridge.c` 调用官方 SDK 已有的 `agent_app_user_corpus()`，让“灵犀”Agent 生成语音回复。原始照片只交给千问，语音 Agent 收到的是文字摘要。千问 API Key 只在本机 `.env.local`，不会写入板端固件。

语音触发路径也已加入：VB701N 在本地等待唤醒词；唤醒后，灵犀的最终 ASR 文字经 USB 串口送到本机预览服务，不传原始麦克风音频。用户选择千问做语义判断，因此预览服务会把**每句唤醒后的最终转写**交给千问文本模型判定是否需要当前摄像头画面。普通对话不调用图像识别；判定为视觉请求时才把一帧 JPEG 交给千问视觉模型，并把“原问题＋简短画面依据”作为一条视觉结果交给灵犀语音 Agent。该路径依赖电脑通过 USB 连接板子且运行 `./lingji.sh preview`。

云端麦克风上行开机默认关闭，本地唤醒后开启；连续 15 秒无对话活动则关闭，下一次唤醒再打开。页面显示固件报告的真实上行状态。等待唤醒词时，语音芯片仍需在本地处理麦克风信号；若要连本地唤醒监听都停掉，须使用实体静音/手动按键，不能同时保持语音唤醒。

普通“描述当前画面”按钮仍只在网页展示结果，不向语音 Agent 发送。语音按钮需要固件同时开启 `CONFIG_APP_CAMERA_TEST=1` 和 `CONFIG_NODEHEXA_VOICE_SELFTEST=0`，并使用本机忽略文件 `project_identity.local.h` 中自己的产品身份构建。烧录前需停止预览服务释放串口，使用 `./lingji.sh flash-app /dev/cu.usbmodem...`；脚本会核验设备和完整 Flash 备份。若分区表或其它镜像改变，应改用 `./lingji.sh flash /dev/cu.usbmodem...`。烧录后重开预览页，先确认画面持续刷新和云端连通，再点击语音按钮听喇叭答复，最后用唤醒词追问同一画面。

串口协议是 `vision <base64-utf8>`，上下文上限 160 UTF-8 字节，低于 SDK 命令行的 256 字节输入限制。内容格式为 `【视觉结果】问题：…；依据：…`，长文本按 UTF-8 边界截短。板端只接收本地串口文本，使用独立任务调用云端 Agent；繁忙、未连云和格式错误均明确返回状态，不打印上下文正文。服务仅绑定 `127.0.0.1`，每次点击最多排队一条视觉消息。模型文字作为不可信观察摘要交给 Agent，不应视为控制命令。平台角色定义已于 2026-10-28 作为原版“灵犀”V2 加入 [视觉协作补充设定](AGENT_VISUAL_CONTEXT.md) 并发布；新版设备端行为仍待复测。

2026-10-26 实测：合并固件已通过 `flash-app` 烧录到 XJWB03，写入哈希校验通过。首次合并启动时遗漏了云端语音分支的摄像头取流启动，页面报 `ESP_ERR_INVALID_STATE`；补上 `bsp_camera_stream_start()` 后重新烧录，预览状态显示 `ready=true` 且帧序号持续增加。一次 `/talk` 请求返回画面描述与 `agent_queued=true`，用户随后确认板上喇叭给出与画面相关的回答，继续问“刚才你看到了什么”也能正常回答。此结果验证了一次按需视觉到语音的闭环和一次追问；长期并行稳定性、语音触发取帧、机器人动作仍待验证。此版本按点击取一帧，不等同于连续视频理解。

随后补充语音意图入口。千问文本意图的真实调用对“现在几点”返回否、对“看看现在桌上放着什么”返回是。用户实测确认：灵犀曾在视觉结果到达前先说“看不到”，随后才收到画面说明并回答，形成割裂的两段话。为此，2026-10-26 重烧的固件和本机服务将“原问题＋画面依据”合并成带 `【视觉结果】` 标记的一条消息，并在板端要求 Agent 只针对原问题作简短归纳；平台角色设定仍需加入等待规则并发布。该固件构建和写入哈希校验通过，预览一度实测 `ready=true`、待机 `cloud=true, active=false, uplink=false`。随后 USB 串口从系统消失，最终双段语音体验尚未复测。当前还没有独立于电脑的部署，也没有连续视频理解。
