# 灵机 XJWB03 与 NodeHexa 运动板接线

两板使用 **3.3 V TTL UART**，115200 baud、8N1。2026-10-28 已实测 UART v2 双向 HELLO/心跳：灵机板状态 `online=1 bench=1 tx=2 rx=2`。当前 `robot_link` 只发送握手和心跳，不发送动作指令；NodeHexa 正运行舵机 PWM 关闭的 USB 联调固件，接好线本身不会让 Agent 控制机器人。后续目标是传递高层动作和状态，由 NodeHexa 负责步态、舵机和安全停止。

## 三根线

| XJWB03（天线朝上、USB-C 朝下，按板上丝印） | NodeHexa 运动板（按照片下排丝印） | 用途 |
| --- | --- | --- |
| 左侧排针 `P17` / GPIO17，UART2 TX | 下排 `P16` / GPIO16，现有固件设为 UART2 RX | 灵机 → 机器人 |
| 左侧排针 `P18` / GPIO18，UART2 RX | 下排 `P17` / GPIO17，现有固件设为 UART2 TX | 机器人 → 灵机 |
| 任意可靠的 `GND` | `GND` | 信号共地 |

NodeHexa 实物没有标着 `RX2` / `TX2` 的针脚；这两个名称表示 UART2 功能。照片中 ESP32 板下排的 `P16`、`P17` 才对应当前代码的 GPIO16、GPIO17；同一排靠右标着 `RX`、`TX` 的针脚属于 USB 下载/日志串口，不要接到本链路。接线以 `P16`、`P17` 的丝印为准，不按整排第几个针脚数位置。

XJWB03 的 `P17`、`P18` 和当前 BF3901 摄像头的 GPIO21/47/4/13/8/41、语音模块的 GPIO40/39/38、日志口的 GPIO43/44 不重合。NodeHexa 的引脚和波特率来自 `firmware/src/board_config.h`，`firmware/src/main.cpp` 已调用 `Serial2.begin()`。接线前仍须核对实物丝印及引脚占用。

## 上电前核对

1. 断开两块板的 USB、电池和舵机电源后接线。两板各自供电，**不要把两板的 5V 或 3V3 电源排针相连**；只共地和连接上述两条 UART 信号。
2. 按丝印逐端确认：灵机 `P17 →` 机器人 `P16`、机器人 `P17 →` 灵机 `P18`、`GND → GND`。TX 必须到对方 RX；不要按杜邦线颜色判断。线尽量短并固定，避免运行时松脱。
3. 用万用表通断档确认线序，并确认 `3V3` 与 `GND` 没有短路。两板均为 ESP32 的 3.3 V GPIO，不要把 5 V 串口或 RS-232 电平直接接到这些引脚。
4. 先分别给两板供电，观察语音、摄像头和机器人状态；当前只验证只读 `HELLO`/心跳。若机器人板已有其它扩展件占用 GPIO16/17，先确认并改线/改配置，不能并联两个 TX 输出。动作功能仍需另行开发和验证。

灵机板调试串口输入 `robot status` 可查询 `online`、`bench`、发送及接收帧计数；先暂停占用同一串口的摄像头预览。`online=1` 且接收计数增长说明握手和回包正常；这不代表已验证动作或舵机供电。

当前视觉模型和语音触发桥接仍依赖电脑通过 **XJWB03 的 USB 调试口**运行本机 `./lingji.sh preview`。这三根线用于以后让灵机板控制 NodeHexa，不能替代目前的电脑视觉服务。完整脱离电脑运行还需要把视觉推理服务迁移或增加独立主机。
