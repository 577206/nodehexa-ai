# 灵机 XJWB03 与 NodeHexa 运动板接线

当前计划用两板间的 **3.3 V TTL UART** 传高层动作和状态，115200 baud、8N1。XJWB03 继续用自己的 Wi-Fi 连接灵机平台；NodeHexa 负责步态、舵机和安全停止。此接线尚未实测，灵机板的 UART2 `robot_link` 驱动尚未写入当前固件；接好线本身不会让 Agent 控制机器人。

## 三根线

| XJWB03（天线朝上、USB-C 朝下，按板上丝印） | NodeHexa 运动板（按其 ESP32 丝印） | 用途 |
| --- | --- | --- |
| 左侧排针 `P17` / GPIO17，计划设为 UART2 TX | `GPIO16` / RX2，现有固件的 UART2 RX | 灵机 → 机器人 |
| 左侧排针 `P18` / GPIO18，计划设为 UART2 RX | `GPIO17` / TX2，现有固件的 UART2 TX | 机器人 → 灵机 |
| 任意可靠的 `GND` | `GND` | 信号共地 |

XJWB03 的 `P17`、`P18` 是候选引脚，和当前 BF3901 摄像头的 GPIO21/47/4/13/8/41、语音模块的 GPIO40/39/38、日志口的 GPIO43/44 不重合。NodeHexa 的引脚和波特率来自 `firmware/src/board_config.h`，`firmware/src/main.cpp` 已调用 `Serial2.begin()`。正式使用前应在两块实物上再次核对丝印及引脚占用。

## 上电前核对

1. 断开两块板的 USB、电池和舵机电源后接线。两板各自供电，**不要把两板的 5V 或 3V3 电源排针相连**；只共地和连接上述两条 UART 信号。
2. 按丝印逐端确认：`P17 → GPIO16`、`GPIO17 → P18`、`GND → GND`。TX 必须到对方 RX；不要按杜邦线颜色判断。线尽量短并固定，避免运行时松脱。
3. 用万用表通断档确认线序，并确认 `3V3` 与 `GND` 没有短路。两板均为 ESP32 的 3.3 V GPIO，不要把 5 V 串口或 RS-232 电平直接接到这些引脚。
4. 先分别给两板供电，观察语音、摄像头和机器人原有功能；再接入 UART 驱动做只读 `HELLO`/状态回传测试，最后才启用受限动作命令。若机器人板已有其它扩展件占用 GPIO16/17，先确认并改线/改配置，不能并联两个 TX 输出。

当前视觉模型和语音触发桥接仍依赖电脑通过 **XJWB03 的 USB 调试口**运行本机 `./lingji.sh preview`。这三根线用于以后让灵机板控制 NodeHexa，不能替代目前的电脑视觉服务。完整脱离电脑运行还需要把视觉推理服务迁移或增加独立主机。
