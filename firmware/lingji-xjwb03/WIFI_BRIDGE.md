# 灵犀 Wi‑Fi 视觉与语音链路

> 历史方案说明：2026-10-30 已切换为 [千问全模态直连](QWEN_DIRECT.md)，不再运行本文下方的灵机云 Agent + 视觉摘要注入链路。当前使用 `./lingji.sh omni`。本文保留用于回退和历史排查。

灵机 XJWB03 通过 5 V USB 供电并接入与电脑相同的局域网；USB 数据线无需保持连接。灵机板提供带令牌鉴权的局域网接口，电脑上的 `camera_web.py` 定时取一帧 JPEG。只有点击“描述当前画面”、点击“描述并让灵犀语音回应”，或唤醒后提出视觉问题时，电脑才把画面发给千问。千问 API Key 保留在电脑的 `.env.local`，不会烧录进灵机板或传给浏览器。

## 本机配置

在被 Git 忽略的 `.env.local` 中配置：

```dotenv
DASHSCOPE_API_KEY=填写自己的千问密钥
LINGXI_BOARD_URL=http://灵机板局域网IP:8766
LINGXI_BRIDGE_TOKEN=与固件中相同的64位十六进制令牌
```

固件构建时从被 Git 忽略的 `secrets.local.h` 读取同一令牌，格式是 `#define CONFIG_LINGXI_BRIDGE_TOKEN "..."`。不要把令牌、产品 SECRET 或千问密钥提交到 Git。灵机板换 Wi‑Fi、路由器重新分配地址后，需要更新 `LINGXI_BOARD_URL` 并重启本机服务。接口只适合可信的本地网络，不要把 8766 端口映射到互联网。

运行 `./lingji.sh preview-wifi`，打开 <http://127.0.0.1:8765/>。网页预览持续更新画面，但不会持续调用千问。唤醒后的最终识别文字才进入本机意图判断；普通对话由灵犀云 Agent 继续处理。待机时固件保持麦克风云端上行关闭。

## 验证顺序

1. 板子接电脑 USB 供电时，先确认云语音、摄像头和网页的 `transport: wifi` 均正常。页面的“描述当前画面”应返回千问短描述。
2. 停止预览服务，拔掉电脑 USB，把灵机板改接可靠的 5 V 电源或充电宝。等待开机、配网、云连接后，单独验证唤醒和普通语音回答。
3. 重新启动 `./lingji.sh preview-wifi`，观察网页画面、唤醒和千问描述是否能稳定并行。如果移动电源下失去唤醒或画面，先停止取图，用电脑 USB 供电做对照；确认供电稳定前不要接入机器人动作。
4. 两板串口的 `robot.online` 状态确认正常、机体架空且供电稳定后，才测试预设动作。机器人电池充电期间不要测试运动。

板载接口包括 `GET /api/status`、`GET /api/frame.jpg`、`POST /api/speak` 和 `POST /api/motion`；每个请求必须带 `X-Lingxi-Token`。板端仅接受固定动作名，语义判断与千问调用都在电脑上进行。两板之间仍使用三线 UART，电脑与灵机板之间改用 Wi‑Fi。

## 当前实测边界

2026-10-30：在电脑 USB 供电时，板端 Wi‑Fi 接口返回 JPEG 和云语音状态，网页按钮用 Wi‑Fi 取得的一帧成功调用千问。调低预览轮询后，USB 供电下已连续取得 390 多帧，串口日志未见崩溃或重启。先前改用充电宝时，接口出现连接重置，唤醒提示音也失效；需继续做移动供电对照。机器人串口回包仍未恢复，不能据此宣布完整无 USB、可运动的闭环通过。
